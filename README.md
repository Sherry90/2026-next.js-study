# 2026 Next.js Study

Next.js App Router 기반 스터디 레포지토리.

## 기술 스택

| 항목         | 버전   | 비고                                                      |
| ------------ | ------ | --------------------------------------------------------- |
| Next.js      | 16.3.1 | App Router, Turbopack (기본 번들러)                       |
| React        | 19.2.8 | React Compiler 활성화 (`next.config.ts`)                  |
| TypeScript   | 6.0.3  | `~6.0.3` 고정. TS 7(Go 네이티브 포팅)은 의도적으로 미적용 |
| Tailwind CSS | 4.3.3  | CSS-first 설정 (`@import "tailwindcss"`), 설정 파일 없음  |
| ESLint       | 9.39.5 | Flat config (`eslint.config.mjs`)                         |
| Prettier     | 3.9.6  | `prettier-plugin-tailwindcss`로 클래스 정렬               |

### 버전 선택 근거

- **TypeScript는 `~6.0.3`으로 고정한다.** npm `latest`는 7.x지만, 6.0은 7.0으로 가는 전환 릴리스이고
  현재 `typescript-eslint@8.x`의 peer 범위가 `>=4.8.4 <6.1.0`이라 6.0이 생태계와 가장 잘 맞는다.
  마이너 업그레이드로 깨지지 않도록 `^`가 아닌 `~`를 쓴다.
- **ESLint는 9 라인을 유지한다.** ESLint 10은 `context.getFilename()` 같은 레거시 API를 제거했는데,
  `eslint-config-next`가 의존하는 `eslint-plugin-react` / `eslint-plugin-import` / `eslint-plugin-jsx-a11y`가
  아직 `^9`까지만 지원한다. 10으로 올리면 lint가 런타임 에러로 죽는다.
- **Vite는 도입하지 않는다.** Next.js 16의 번들러는 Turbopack이고, Vite와는 모듈 그래프를 소유하는
  동일 계층이라 공존할 수 없다.

## 시작하기

```bash
pnpm install
pnpm dev          # http://localhost:3000
```

## 스크립트

| 명령                | 설명                          |
| ------------------- | ----------------------------- |
| `pnpm dev`          | 개발 서버 (Turbopack)         |
| `pnpm build`        | 프로덕션 빌드                 |
| `pnpm start`        | 빌드 결과 실행                |
| `pnpm lint`         | ESLint 검사                   |
| `pnpm lint:fix`     | ESLint 자동 수정              |
| `pnpm typecheck`    | 라우트 타입 생성 후 타입 검사 |
| `pnpm format`       | Prettier 포매팅 적용          |
| `pnpm format:check` | 포매팅 검사 (CI용)            |

> `typecheck`는 `next typegen && tsc --noEmit`이다. `tsconfig.json`이 `.next/types/**/*.ts`를
> include하므로 `LayoutProps` / `PageProps` 같은 Next 전역 타입은 생성되기 전에는 존재하지 않는다.
> `next typegen`이 풀 빌드 없이 그 타입만 만들어 주기 때문에 클린 클론 직후에도 단독으로 돌아간다.

## Git 컨벤션

### 브랜치

```
main                 # 항상 배포 가능한 상태. 직접 푸시 금지
feat/<주제>          # 기능 추가
fix/<주제>           # 버그 수정
docs/<주제>          # 문서
chore/<주제>         # 설정, 의존성, 빌드
refactor/<주제>      # 동작 변경 없는 구조 개선
```

예: `feat/server-actions-form`, `fix/hydration-mismatch`

### 커밋 메시지

[Conventional Commits](https://www.conventionalcommits.org/)를 따른다.

```
<type>(<scope>): <subject>

<body>

<footer>
```

**type**

| type       | 용도                            |
| ---------- | ------------------------------- |
| `feat`     | 기능 추가                       |
| `fix`      | 버그 수정                       |
| `docs`     | 문서만 변경                     |
| `style`    | 포매팅 등 동작에 영향 없는 변경 |
| `design`   | 디자인관련 변경사항             |
| `refactor` | 리팩터링                        |
| `config`   | 설정 관련 변경사항만            |
| `build`    | 빌드 관련 변경사항만            |
| `perf`     | 성능 개선                       |
| `test`     | 테스트 추가/수정                |
| `chore`    | 빌드, 설정, 의존성              |

**규칙**

- subject는 한글 또는 영어, **50자 이내**, 마침표 없음
- subject는 명령형 현재시제로 쓴다 (`추가한다` / `add`, `추가했음` / `added` 금지)
- body는 **무엇을 했는지가 아니라 왜 했는지**를 쓴다. 무엇은 diff가 말해준다
- body는 72자에서 줄바꿈
- 커밋 하나는 하나의 논리적 변경만 담는다
- Breaking change는 footer에 `BREAKING CHANGE: <설명>`

**예시**

```
feat(auth): 소셜 로그인 콜백 라우트 추가

Route Handler에서 세션 쿠키를 굽도록 했다. Server Action으로는
Set-Cookie 헤더를 리다이렉트 응답에 실을 수 없어 라우트로 분리했다.
```

### Pull Request

- 제목은 커밋 메시지와 동일한 컨벤션을 따른다
- 머지 전 아래가 모두 통과해야 한다

  ```bash
  pnpm typecheck && pnpm lint && pnpm format:check && pnpm build
  ```

- 머지 전략은 **Squash and merge**를 기본으로 한다

## AI 도구 사용 규칙

AI 코딩 도구(Claude Code, Copilot, Cursor 등) 사용은 자유다.
다만 **커밋과 PR에는 AI가 관여했다는 흔적을 남기지 않는다.**

### 반드시 제거할 것

커밋 메시지 / PR 본문에서 아래 항목을 **커밋 전에** 지운다.

- `Co-Authored-By: Claude <noreply@anthropic.com>` 등 AI를 공동 작성자로 넣는 trailer
- `🤖 Generated with [Claude Code](https://claude.com/claude-code)` 류의 생성 배너
- `Generated by ...`, `Created with ...`, `AI-assisted` 같은 문구
- 도구 이름이 들어간 이모지 서명 (`🤖`, `✨ by ...`)

코드에서도 마찬가지다.

- `// AI가 생성한 코드`, `// TODO: AI 검토 필요` 같은 주석
- 프롬프트 원문이나 대화 로그가 남은 주석 블록
- 실제로 쓰지 않는데 AI가 만들어 둔 파일

### 왜

커밋 로그는 **변경의 이유**를 기록하는 곳이지 **작성 도구**를 기록하는 곳이 아니다.
`vim으로 작성함`을 커밋에 적지 않듯 AI 서명도 적지 않는다.
그리고 커밋에 이름이 올라간 사람이 그 코드의 책임자다 — AI는 책임을 질 수 없으므로
공동 작성자로 올리지 않는다. **AI가 썼든 사람이 썼든, 커밋한 사람이 전부 이해하고 책임진다.**

### 커밋 전 확인

```bash
# 스테이징된 변경에 AI 흔적이 있는지 확인
git diff --cached | grep -niE "claude|copilot|cursor|generated with|co-authored-by|🤖"

# 직전 커밋 메시지 확인
git log -1 --format=%B | grep -niE "claude|copilot|generated with|co-authored-by|🤖"
```

걸리는 게 있으면 커밋하지 말고 정리한다. 이미 커밋했다면 푸시 전에 고친다.

```bash
git commit --amend        # 직전 커밋 메시지 수정
git rebase -i <base>      # 여러 커밋 정리
```

### `AGENTS.md` / `CLAUDE.md` 는 예외다

`next dev`는 `AGENTS.md`와 `CLAUDE.md`를 자동으로 생성/복원한다. 이건 AI 서명이 아니라
"이 Next 버전은 학습 데이터와 다르니 `node_modules/next/dist/docs/`를 읽어라"라고 지시하는
Next.js 기능 파일이다. 지우면 `next dev`가 다시 만들기 때문에 선택지는 둘 중 하나다.

- **추적하지 않는다 (현재 설정)** — `.gitignore`에 넣어 워킹 트리를 깨끗하게 유지한다.
- **커밋한다** — Next 공식 권장. 에이전트가 최신 API 기준으로 코드를 쓰게 하려면 이쪽이 낫다.

바꾸려면 `.gitignore`의 `/AGENTS.md`, `/CLAUDE.md` 두 줄을 지우면 된다.
